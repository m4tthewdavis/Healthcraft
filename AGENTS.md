# AGENTS.md: guide for AI agents and contributors

HealthCraft is an open-source, research-native electronic health record written in **Rust only**
(no JavaScript or TypeScript). **No Tauri, Electron or webview shells:** the desktop app is native
egui/eframe on wgpu, and the browser build (`apps/healthcraft-web`) is the same Rust compiled to
WebAssembly. The
product name is always written **HealthCraft** in user-facing text; machine names stay lowercase
(`healthcraft-*` crates, binaries, ids). Read this file first, then `docs/`.

## 2. Workspace map

```text
crates/
  core                L0  typed ids, Actor/Role, Clock, IdSource, input limits
  terminology hl7v2   L0  standalone (no workspace deps; publishable)
  record audit        L1  ClinicalEvent + Chart projection · hash-chained access log
  store               L2  EventStore trait, optimistic concurrency, InMemoryStore
  fhir research       L3  FHIR R4 projection + bundle import · OMOP CDM + Safe Harbor
  engine              L4  Session + command registry: authorize, run, audit
  api ui-egui         L5  axum HTTP API · egui clinician UI
  testkit                 test helpers (dev-dependency only)
apps/                     healthcraft (desktop), healthcraft-web (browser), healthcraft-server, healthcraft-cli
xtask/                    cargo xtask layers | wasm | web | ci
fixtures/                 synthetic test data only
```

**Layering is enforced** by `cargo xtask layers`: a crate depends only on lower layers;
`terminology` and `hl7v2` depend on no workspace crate; nothing below L5 may use egui, eframe,
winit, wgpu, axum, tokio, tower or hyper. Register a new crate in `xtask/src/layers.rs`.

## 3. Golden rules

### Patient safety and privacy (outrank everything)

- **Synthetic data only.** Never commit, paste into an issue, log, or use in a test any real
  patient data, including "de-identified" data. Fixtures are invented by hand or generated by
  Synthea, and say so.
- **Never lose or rewrite clinical history.** The record is append-only. A correction is a new
  event (`DemographicsAmended`, `ObservationEnteredInError`) with a reason; never add an update or
  delete path to the store.
- **Every access is authorized and audited.** New behaviour goes through `Session::dispatch`, which
  checks the role and writes the access log. UIs, the API and the CLI never touch the store.
- **No AI writes to a chart without a human.** When agent access (MCP) lands, agents may draft;
  a clinician signs.
- **Clean-room.** Study other EHRs' *behaviour* only. Never copy their code, screens, help text,
  order sets or content. Implement from public standards (FHIR, HL7 v2, OMOP, US Core, USCDI).
- **Terminology licensing.** Never commit CPT or SNOMED CT content (or any terminology file).
  Code system URIs and loaders only; see `NOTICE`.

### Never crash

A clinician mid-visit cannot lose work to a panic. A malformed bundle, a hostile HL7 message, a bad
command parameter or a full disk must produce an error the user or agent can act on.

- **Non-test code never panics.** No `unwrap()`, `expect()`, `panic!`, `unreachable!`, `todo!`,
  `unimplemented!`, or unchecked indexing (`v[i]`, `&s[a..b]`, `json["key"]`). The workspace lints
  deny all of these outside tests (`Cargo.toml`, `clippy.toml`). Return the crate's error type.
- **No `unsafe`.** `unsafe_code = "forbid"` workspace-wide.
- **Input is hostile.** Cap sizes before allocating (`healthcraft_core::limits`, the parsers'
  `MAX_*` constants), use `checked_*`/`saturating_*`, slice strings only at char boundaries.
- **Don't cascade.** Recover poisoned locks with `unwrap_or_else(PoisonError::into_inner)`.
- **Prove it.** A crash fix ships with a regression test. `crates/engine/tests/panic_hunt.rs` runs
  every command with hostile parameters and must stay green.

### Engineering

1. **Everything is a command.** New user-visible behaviour = a command in
   `crates/engine/src/<area>_cmds.rs` (`specs()` registered in `registry()`), with id, label, params
   doc, `Access` and `run`, plus tests. See `CONTRIBUTING.md` › Adding a command.
2. **The domain is deterministic.** Time comes from `Clock`, ids from `IdSource`; never call
   `Utc::now()` or generate random ids in L0–L4. Time goes through `chrono`.
3. **Never break wasm.** L0–L4 must pass `cargo xtask wasm`.
4. **Tests are the gate.** Every change comes with tests; parsers get malformed-input tests.

## 4. Before you finish a task

```sh
cargo fmt --all
cargo clippy --workspace --all-targets -- -D warnings
cargo test --workspace
cargo xtask layers
cargo xtask wasm          # if you touched L0-L4
# or all of the above, as CI runs it:
cargo xtask ci
```

## 5. Parallel agents

- Use your own target dir (`CARGO_TARGET_DIR=target/agent-<name>`) and edit only files you own.
- Put new commands in a **new module** rather than growing a shared file.
- Keep every `Cargo.toml` valid at all times: the `crates/*` glob means one broken manifest breaks
  everyone's build.
